# 12 实施计划与 Agent 开发契约

版本 HL-DOC-1.0.0，FROZEN。适用于未来实施；当前用户任务只授权文档，不启动此计划中的代码开发。

## 1. Agent 必须遵守

1. 开工先读README及00/01/03/04/07和当前专项，验证清单hash；先检查工作树、已有实现、AGENTS与执行记录，不根据聊天记忆重写。
2. 只实现任务要求，不把GPU、ALS、事务发布等难项降为可选。训练不成功不能填造checkpoint、loss、指标或硬件信息。
3. 不修改冻结基线去迁就实现；发现冲突列明字段/需求/测试影响，按00治理。新用户明确改变任务时以新指令为先。
4. 不在根目录创建未授权的实现，也不在本轮生成样例程序、DDL、配置脚本；未来开发授权到达后才建立下述工程目录。
5. 对外接口/数据schema不自行改名；测试数据不得被生产发布器当真实数据；不把synthetic推荐指标当真实评价。
6. 仅在明确允许的范围编辑；不覆盖用户变更；不format HDFS、不重置数据库凭据、不全局升级CUDA/Java/Python。
7. 测试按当前改动与11要求执行，报告未运行项与原因；不能凭编译通过宣称GPU训练成功。
8. task状态只由真实句柄与产物核验推进，不把沉默/超时视为失败或用户同意。保持可续跑的run与证据，避免重复重任务。

## 4. 每个任务包的交接

交接记录包括目标FR/NF、输入契约和输出路径、改动文件、迁移/兼容影响、配置hash、实际测试与结果、未完成项、下一任务依赖。出现阻塞要保存当前证据，区分可继续的实现和等待设备/网络的验收，不用空文档或TODO占位宣称实现。

代码Review至少检查：金额与时区、NULL协议、订单distinct、split泄漏、候选一致、GPU设备、checkpoint来源、FK与发布原子性、API只读、release固定、凭据脱敏。UI布局等常规选择可自行决定，不必为可逆细节反复问用户。

## 5. 完成定义

任务包完成需本包功能存在、对应测试通过、真实证据可定位、接口契约未漂移、执行记录更新。整个项目完成需FR-01—12、NF-01—08及T-01—20全部验证，最终四算法真实数据指标、GPU证据、发布与恢复、页面和报告齐全。

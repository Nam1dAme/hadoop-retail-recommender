# 02 页面与交互规范

版本 HL-DOC-1.0.0，FROZEN。

## 1. 全局行为

Streamlit 中文界面；左侧导航七页。顶部显示 release_id、batch_id、数据日期范围、币种 GBP、来源时间语义、当前推荐算法和数据版本。页面打开先获取当前 release，之后所有请求携带该 release_id；刷新版本需要用户明确点击“切换到当前版本”，不在页面中途自动漂移。

筛选以“应用”提交，清空恢复该页默认值。日期含首含尾，默认当前 release 数据全区间；国家默认全部。非法范围在客户端提示，同时 API 仍独立校验。每次切页保留固定 release。切版本清空客户/商品等可能失效的选择，避免旧标识误配新数据。

金额显示 £ 与两位小数；API 返回十进制字符串，UI按十进制处理，图形坐标允许转浮点但表格和导出必须保留精度。无分母的比率显示“—”，不显示0%冒充已计算结果。所有“客户”是公开数据标识，不展示为真实个人档案。

## 2. 页面规范

| 页面 | 输入 | 展示 | 状态规则 |
|---|---|---|---|
| 总览 | 日期、国家 | 正向销售额、退货金额、净额、有效订单数、客单价、日趋势、Top20商品 | KPI与榜单同筛选；总客户数标签注明仅正向且CustomerID有效 |
| 销售分析 | 日期、国家、日/月粒度、商品榜排序 | 趋势、国家排行、商品销售排行，明细分页 | 按国家筛选后国家排行最多该国家，不偷偷忽略筛选 |
| 客户分层 | segment、customer_id、分页 | RFM数值、分数、分层分布、基准日 | 本页为批次全历史快照，不提供日期/国家筛选 |
| 商品关联 | stock_code、K=1..10 | 商品描述、关联商品、similarity、co_count、confidence、lift | 不受销售页日期筛选；商品不存在404，存在无关联为空态 |
| 客户推荐 | customer_id、algorithm、K=1..10 | 排序商品、分数、方法、fallback与原因 | 四算法可切换；默认release指定champion；未知客户热门兜底并提示 |
| 模型实验 | experiment_id、algorithm | 共同评价人数/候选规模、四算法指标、NCF损失、CPU/GPU性能、设备参数 | 评估结果与全量服务模型分开展示；未做GPU时显示未验收 |
| 数据质量与任务 | batch_id/run_id、状态 | 分类计数、缺失/重复/超大篮子、DAG状态、耗时、application ID、错误 | 不显示凭据或完整敏感日志；只读，不出现重试按钮 |

推荐原因固定 reason_code 与中文文案：POPULAR=“训练/服务历史热门商品”；CO_PURCHASE=“与你购买的商品存在同单关联”；LATENT_FACTOR=“根据历史购买偏好推荐”；NEURAL_CF=“根据神经协同过滤模型推荐”；FALLBACK_POPULAR=“当前模型信息不足，使用热门商品补足”。NCF/ALS不得生成不存在的“朋友喜欢”“同年龄客户购买”等解释。

## 3. 空态、加载和失败

- 首次无 release：展示“尚无可用数据版本”，模型实验和任务页仍可查看已记录任务，业务页禁用筛选提交。
- 加载：指示请求进行中，避免重复点击；客户端请求超时5秒，不无限转圈。
- 筛选无结果：KPI金额为0、订单为0、客单价为空；列表为空数组，提示缩小筛选。禁止回退显示全量数据。
- API不可用：保留用户输入，显示请求ID和重试操作；不可伪造成功或使用无标识的旧缓存。
- 推荐不足K：显示实际条数与eligible_candidates，不填入已购/重复商品。
- 旧release已清理：提示版本不可用，允许重新选择当前版本；不得自动换版本混合结果。

## 4. 图表和可访问性

趋势图横轴按来源日期排序；国家及商品条形图默认Top20，显示排序依据与GBP单位。RFM分层使用固定标签与文本图例，不能仅凭颜色表达。支持表格查看图形数据，不依赖GPU进行页面渲染。页面标题、筛选名称、错误提示中文清楚；不把内部堆栈显示给普通用户。

1.0 不做导出端点；运行报告中的结果表由离线报告步骤生成，避免网页新增未约定接口。

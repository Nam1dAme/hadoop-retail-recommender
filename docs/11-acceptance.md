# 11 测试与验收规范

版本 HL-DOC-1.0.0，FROZEN。本文件定义未来实现必须提供的证据，不表示本轮已运行这些业务测试。

## 1. 验收门禁

按G-DOC（设计可追溯）→G-ENV（环境依赖与GPU）→G-DATA（数据质量）→G-MR（业务YARN）→G-MODEL（四算法训练/评价）→G-GPU（真实GPU训练及对照）→G-RELEASE（原子发布）→G-APP（API/UI）→G-RECOVERY（恢复与报告）执行。G-ENV的GPU未通过不妨碍实现其他模块，但最终完成必须全部通过。不能通过改文档或删除测试缩小门禁。

## 3. 时间评价样例

独立构造已知用户u、TRAIN已购A、候选C={A,B,C,D}，测试真实未购相关G={B,D}；推荐[B,C,D]（列表实际3项，K仍10）。期望Precision=0.2、Recall=1、DCG=1+1/log2(4)=1.5、IDCG=1+1/log2(3)，NDCG约0.9197208。TRAIN已购A不能出现在推荐中；未来购买不能用于排除TRAIN负样本。测试目录外商品E不进入G但计入cold item与排除统计。

全局split必须把2011-08-31放TRAIN、2011-09-01放VALIDATION、2011-10-31放VALIDATION、2011-11-01放TEST，按订单整组不跨窗。同用户验证购买不得进入TEST模型历史。

## 5. 自动化与人工证据边界

数据和模型评价逻辑必须自动化断言；API按契约做集成测试；GPU实际训练、CPU/GPU对照、YARN业务、数据库恢复不能用mock替代最终证据。页面除接口集成与关键流程验证外可人工截图验收，不为低影响样式写镜像实现的测试。

金额零容差、整数计数零容差；double公式测试绝对误差≤1e-6；同设备固定环境重跑指标差异>1e-5需解释。CPU/GPU允许浮点和排序近似差异，不要求权重逐位相等，不能借此放过NaN、映射错位或候选不同。

每条结果记录test_id、baseline、代码commit、环境hash、数据hash、run/experiment/release、命令或操作、UTC时间、实际结果、证据路径、PASS/FAIL/NOT_RUN。NOT_RUN不能计为通过；文档校验不能替代实现验收。最终交付附五分钟演示路线：数据质量→YARN任务→销售/RFM→推荐对比→GPU训练/性能→发布版本与回滚证据。

# 00 文档治理与冻结规则

基线：HL-DOC-1.0.0；状态：FROZEN；生效日期：2026-10-18。

## 1. 约束等级与权威性

“必须”是验收条件；“建议”是允许记录理由后替换的实施细节；“可选”不影响 1.0 完成定义。本基线全部功能需求 FR-01—FR-12 和非功能需求 NF-01—NF-08 均为必须，不得把 NCF/GPU、ALS 或接口测试降为可选以提前结项。

权威顺序：用户新指令 > 经用户接受的新基线变更 > 本基线专项契约 > PRD > 架构概述 > 历史讨论与目录外文档。专项权威：数据口径以 04、作业协议以 05、存储以 06、训练评价以 07、HTTP 以 08、版本及部署以 09、验收以 11 为准。遇到这些文档之间的矛盾，先列影响并解决，不可自行宣称一种覆盖另一种。

开发时不得修改 FROZEN 文档去适应错误实现。用户明确要求改变范围时才开启变更；用户新指令优先，不能用冻结规则拒绝已授权修改。

## 2. 变更规则

变更记录至少包含 CR-ID、提出人/日期、理由、受影响 FR/NF、表/字段/API/数据口径/模型影响、迁移与回滚、验证项、用户指令证据。只更新文案且不改变语义可升 patch；新增向后兼容功能升 minor；改变金额口径、split、主键、响应语义或移除必做功能升 major。每次变更重跑全量文档审查并更新清单，历史版本通过 Git 历史保留。

运行结果、硬件观测、真实性能、依赖解析锁和实现进度属于执行记录，不改变本基线的已定设计；放入后续 `docs/execution/` 并标注引用基线版本。实现阶段产生的精确依赖锁应存代码仓库配置目录，不把“文档冻结”等同于已解析出全部传递依赖。

## 3. 标识与命名

| 标识 | 固定规则 |
|---|---|
| baseline_version | HL-DOC-1.0.0 |
| schema_version | 数据与 API 为 1.0；数据库迁移起点 001 |
| batch_id | B 加 UTC 年月日时分秒再加 8 位小写十六进制随机串，CHAR(23) |
| run_id | UUID，CHAR(36)，单个任务尝试执行的 ID |
| model_run_id | UUID，CHAR(36)，训练或基线构建的逻辑模型 ID |
| release_id | R 加 UTC 年月日时分秒再加 8 位小写十六进制随机串，CHAR(23) |
| experiment_id | UUID，CHAR(36)，一组切分与四算法评价的共同 ID |
| attempt | 从 1 开始；每次重试产生新 run_id 并递增 attempt |

字段名 snake_case，枚举全大写，算法枚举固定 `POP/ITEMCF/ALS/NCF`。所有排序平局最终以 stock_code 的 UTF-8 字节序升序打破，客户列表以 customer_id 同序；数据库涉及业务标识使用二进制排序规则，不能依赖系统默认大小写折叠。

## 4. 时间、金额与版本约束

数据源时间是来源当地墙钟时间，无可靠时区标识；以 `source_local` 原样处理，禁止当作北京时间转换。运行审计时间统一 UTC；所有 API 运行时间为带 Z 的 ISO 8601。金额仅 GBP；计算使用整数便士，展示与数据库货币使用两位小数十进制。

原始文件 hash、数据策略版本、split 配置、算法超参数、环境锁 hash、代码 commit、随机种子和基线版本必须可追溯。源代码尚无 commit 时只能标记开发试跑，不准构建正式 release。

## 5. 冻结与实际完成的区别

本基线允许环境未知，但不允许业务设计待定。GPU 型号/显存/驱动、宿主 VHDX 所在盘、实测耗时属于待采集事实，处理规则已在 09/11/13 定义。无法使用 GPU 时可继续 CPU 调试及非 GPU 模块，但全项目 GPU 验收仍保持未完成。

校验清单覆盖本目录全部基线文件，清单自身不自哈希；16 审查记录先完成，再计算清单。文档可写权限不等于允许改动冻结语义，不采用 chmod 只读阻碍正常版本管理。

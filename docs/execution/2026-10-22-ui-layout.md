# 筛选栏对齐与侧栏收起居中修复

日期：2026-10-22；基线 HL-DOC-1.0.0。对应用户反馈：应用/清空按钮与旁边下拉栏错位，侧栏收起后正文没有重新居中。

## 原因与修复

原筛选栏在动作按钮前插入固定25px的HTML占位，再叠加容器间距，使按钮底边比下拉栏低11px。移除所有六处占位，改用 Streamlit 原生 `st.columns(vertical_alignment='bottom')`；日期、文本、数值输入和表单按钮统一40px最小高度，下拉栏保持原生40px。覆盖总览、销售分析、客户分层、商品关联、客户推荐、模型实验及数据质量与任务。

原侧栏无论展开与否都强制最小宽度238px。收起时虽然被平移到屏幕外，仍保留238px的flex空间。现仅在 `aria-expanded=true` 时固定238px，收起时宽度、最小/最大宽度和边框归零；正文保持最大1600px，并在可用区域内水平居中。

沿用现有蓝灰配色、字体、页面内容和数据语义。筛选仍需点击应用，清空和分页、固定版本及只读API访问方式保持原行为。仅重启项目UI进程加载代码，API和数据库未重启。

## 实测结果

1920px宽屏原始状态：侧栏收起后main仍从x=238开始，正文容器x=279、宽1600，中心偏右。修复后main从x=0开始、宽1920，正文x=160、宽1600，左右留白各160px。1440px收起后main和正文均从x=0开始、宽1440；重新展开后恢复侧栏对应的可用区域居中。

应用和清空与同排筛选框上下边缘一致，控件高度40px。手机端保留原有换行布局，按钮与同排控件对齐。

- `uv run --locked --no-sync python -m pytest tests/test_ui.py -q`：13项通过；仅既有Starlette/AnyIO弃用警告。
- 实际Chromium七页及交互检查：272项通过，23张截图/几何记录，覆盖1920、1440、1024、768、390、360px；JavaScript错误和外部运行时资源请求均为0。
- 新增几何断言覆盖按钮高度/底边、相邻输入控件、正文中心，以及1440/1920px侧栏展开、收起和重新展开。首次几何检查发现日期框原生高度约37.6px，已统一最小高度后完整复查通过。
- 训练、模型、发布数据、数据库结构和冻结文档未修改；未运行MR或GPU训练。

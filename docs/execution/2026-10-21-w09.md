## 输入、范围与结果

正式输入为 W08 的 READY 版本 `R20261021104550ac6985a5`，批次 `B20261019194025b4f65854`，实验 `acea8dc1-3b09-43b8-ac79-09571cfcca53`，默认算法 ALS。源文件 SHA-256 为 `43465a06f2ccf7c8b5bd2892bc7defb52f97487934fe93b16ae4c3936424676d`。

完成 08 定义的全部 20 个只读 GET 端点：健康与版本 4 个，销售 4 个，客户 2 个，关联与推荐 2 个，批次与质量 2 个，任务 2 个，实验/指标/训练曲线/benchmark 4 个。覆盖 FR-03—08 的查询展示入口、FR-09 的版本固定、FR-10 的 API 部分、FR-11，以及 NF-01/04/06/07/08 的相关约束。

实现与手工复核重点：

- 每请求独立的 REPEATABLE READ / READ ONLY 事务；缺省版本只读取 current 一次，后续业务 SQL 显式携带该 release_id。READY 旧版本可查，BUILDING/FAILED 为 409，RETIRED 为 410，无 current 为 404；批次/任务/实验查询不依赖 current。
- 统一 typed response、UUID 请求 ID、JSON 错误；未知/重复参数、非法 ID/日期/排序/分页/k 与 GET body 均拒绝。日期超出来源范围取交集，空列表返回 200，空订单客单价为 NULL；金额使用 Decimal/HALF_UP 两位字符串。
- cube 统计金额，sale_order 统计 distinct 客户及订单，商品订单来自独立的 sale_order_item 查询，避免 join 放大。商品榜先分页，再使用现有 `(release_id,stock_code,invoice_no)` 索引统计当前页商品订单，无新增索引或迁移。
- MariaDB `utf8mb4_bin` 仍有 PAD SPACE 比较语义；查询将绑定参数转换为 BINARY，确保 `UK ` 与 `UK` 等输入精确区分，保留索引列本身。
- 推荐读取对应 FULLFIT 模型；四算法未知客户按热门兜底但不更换 model_run_id；POP 自身为 POPULAR、不算 fallback；覆盖没有合格模型历史的 RFM 客户及全目录已购空列表。
- 指标只引用 experiment_model 选定 EVAL；NCF EVAL/FULLFIT 曲线分开，非 NCF 返回空数组。benchmark 只读选定 EVAL NCF 的实际六次记录，不训练或修改模型。
- benchmark 完全无记录时 409；已有部分记录时按 08 专项 summary 规则返回现有 items，无效/不足时摘要三数值为 NULL，不能计算误导性的加速比。

## 权限、部署与兼容

`service/` 增加参数/响应类型、只读数据库会话、查询仓库、错误封装、应用工厂及显式 CLI 启动。`orchestration.database` 仅增加可选连接时限参数，原默认行为保持；`orchestration.provision` 增加两列 SELECT，迁移 001 与表结构均未修改。

原 reader 缺少 `task_run.log_path` 和 `data_batch.quality_report_path`；项目账号没有 GRANT OPTION，sudo 需要用户密码。已生成 `scripts/w09-reader-grants.sql`，用户在本轮明确回复“已执行”，随后真实连接核验两列权限生效。API 只查询 `IS NOT NULL` 并返回登记布尔值，不返回对应路径、不访问文件。原 W02 权限测试相应更新为允许这两列并继续拒绝 source_url、pid、process_start_utc 和写入。

真实 reader 最小授权检查仍通过：`minimum_grants_match=true`，CREATE、迁移历史写入、控制表写入、来源 URL 与进程 PID 查询均被拒绝。用 writer 凭据启动服务实际退出 2，且只有脱敏的启动检查失败提示。SQL 参数绑定、排序白名单、无写入口、仅回环监听；启动和每请求均拒绝带写权限账号。

实际启动命令：

```bash
source scripts/dev-env.sh
uv run --locked python -m service \
  --config config/development.toml \
  --db-defaults-file var/secrets/reader.cnf
```

实际监听为 `127.0.0.1:8000`，不信任转发头、不启用 CORS 通配，关闭包含原始 URL 的访问日志。数据库不可达/迁移不匹配、SQL 超过两秒或 HTTP 总预算五秒时使用 503；ready 失败还带 `data.status=NOT_READY`。诊断日志不输出异常文本、SQL 或堆栈；任务旧 error_message 使用脱敏文案和稳定 error_code。

## 实测与证据

完整机器证据见 [w09-verification-2026-10-21.json](w09-verification-2026-10-21.json)。真实 HTTP 验证运行时 HEAD 为上述实现提交，`tracked_code_dirty=false`；未提交静态 Demo 与 API 无关。配置及环境锁摘要、Python/库版本、数据/实验/版本 ID、请求耗时和逐表摘要均在 JSON 中。

| 验证 | 结果与边界 |
|---|---|
| T-15/T-17 隔离契约与安全用例 | W09 新增 45 个 pytest 用例；独立真实 MariaDB，不在正式库/HDFS 注入 fixture |
| 最终全量回归 | `uv run --locked python -m pytest -q --maxfail=2`：178 passed，171.29 秒，零失败/跳过；仅 Starlette/AnyIO 既有弃用提示 |
| 真实 HTTP 与独立 SQL 对照 | 43 次顺序 HTTP 请求覆盖 20 端点及必要变体，265 项检查通过；验证器不导入 API 查询实现 |
| 正式库不变性 | 前后 23 张表、1,328,636 行的 reader 可见列摘要完全相同；未授权控制列不在摘要范围内，不能声称全列审计 |
